# Issue #56 — Tag Aggregate and Persistence Design

**Status:** Owner-approved design, 2026-10-31. **Issue:** https://github.com/krishna916/horizon/issues/56
**Parent:** #8. **Downstream:** #57 (tag.api resolution/suggestions), then #27 (Task integration).

## Intent and scope

Provide a tested, user-owned Tag reference aggregate within the existing Tag module. This issue owns the entity, internal repository, Flyway PostgreSQL schema, owner-scoped uniqueness and tests. It is independently mergeable without UI, public APIs or Task/Note associations.

## Approved decisions

1. **Name equivalence:** strip surrounding whitespace; within a user, use PostgreSQL lower(name) as the persisted case-insensitive identity. Do not claim full Unicode normalization or Unicode case-folding. Allow Unicode, symbols and internal spaces.
2. **Display:** retain the first persisted name's casing/spelling. No normalized-name column, rename or case-changing side effect.
3. **Validation:** null/empty/whitespace-only invalid; maximum **100 Unicode code points** after trimming; reject ISO controls including tabs/newlines; preserve internal whitespace/casing and accept non-Latin characters. For consistency, reject ISO controls in raw input before trimming, and trim edge code points satisfying Java Character.isWhitespace or Character.isSpaceChar (including non-breaking spaces).
4. **Uniqueness:** functional **unique** index on (user_id, lower(name)), not citext or a stored normalized key. Different users can use the same tag name.
5. **Ownership:** scalar immutable Long userId with foreign key to users(id); no JPA @ManyToOne dependency on user.domain.
6. **Base type:** extend shared.domain.BaseEntity for id/createdAt/updatedAt only. No inbox, status, archivedAt, deletedAt, completedAt, join collections or automatic cleanup.

## Product and architecture reconciliation

SPEC-002 defines Tag as its own entity (name and timestamps) that persists after its last association, with no archive/trash/review lifecycle. Owner-scoping in #56 and the Constitution adds user_id to that narrower field example. SPEC-001's content lifecycle fields apply to Task/Note content, not to Tag. PRD-004's Task status filter and derived active/completed/archived views are *not* a persisted Tag status or a reason to add a Task status enum. Module ownership and the user-based repository access follow the Constitution.

Existing repository files are authoritative when the older HORIZON_STATUS conflicts: server/pom.xml and server/AGENTS.md use **Java 25, Spring Boot 4.0.6 and PostgreSQL 17**. Existing BaseEntity has only identity and timestamps; Task.java already models ownership with scalar Long userId. Hibernate runs schema validation, Flyway owns creation.

## Schema and model

~~~sql
CREATE TABLE tag (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY,
    user_id BIGINT NOT NULL,
    name VARCHAR(100) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL,
    CONSTRAINT pk_tag PRIMARY KEY (id),
    CONSTRAINT fk_tag_users FOREIGN KEY (user_id) REFERENCES users(id),
    CONSTRAINT ck_tag_name_trimmed CHECK (name <> '' AND name = btrim(name))
);
CREATE UNIQUE INDEX uk_tag_user_name_ci ON tag (user_id, lower(name));
~~~

Java-side validation handles Unicode/control-character details; SQL constrains storage, ordinary surrounding spaces, nonempty values, FK and concurrent uniqueness. PostgreSQL VARCHAR(100) counts characters/code points, not Java UTF-16 units. Do not add a JPA @UniqueConstraint for the expression index: validate it through real PostgreSQL tests.

Domain: Tag extends BaseEntity; protected JPA constructor; static Tag.create(Long userId, String name), getter-only immutable userId/name; InvalidTagException with field="name" analogous to InvalidTaskException.
Infrastructure: internal TagRepository extends JpaRepository<Tag,Long> and owner-scoped findByIdAndUserId(Long,Long). No Tag web/application/public API for this issue.

## Alternatives rejected

A normalized_name column introduces duplicated state/synchronization. citext introduces an extension/specialized type without V1 necessity. A User JPA relationship couples Tag to another module's internals. A Java-only duplicate pre-check fails concurrency.

## Acceptance and boundaries

Test ASCII case variants Horizon/horizon/HORIZON for one owner, same name under different owners, missing FK, raw invalid DB writes, 100/101 code points (including supplementary characters), preserve casing and timestamps, owner-scoped reload, no cleanup, and concurrent independent insert transactions where exactly one commits and loser receives SQLSTATE 23505.

**Deferred:** #57 owns create-or-reuse resolution, collision recovery, suggestions, public tag.api, HTTP; #27 owns Task-tag assignment. Do not add Task/Note join tables, UI, tag management, rename/merge/delete, Search-by-tag, status or lifecycle fields, dependencies or generic abstractions.

**Execution:** Use the companion Superpowers plan. Raise genuinely new product-semantic conflicts, but do not reopen decisions approved here.
