**Goal:** Complete the restart-safe File-owned recovery queue, physical deletion retries, conservative UNKNOWN reconciliation and terminal compaction without deleting live objects or losing possibly late PUT locators.

**Architecture:** Extend #76's two PostgreSQL tables, existing File service and storage port. Only a DELETE initiated after authoritative write settlement can confirm terminal cleanup. No Note callbacks or cross-module repositories.

## Review focus (additional regression tests)

1. **Clock reversal / waited lock:** expiry fence cannot reopen after DB time moves backwards; lock acquisition uses fresh DB time (Task 2).
2. **Delayed duplicate completion:** already selected verified replay is a no-op; late/stale UNKNOWN cannot downgrade settlement or re-add purged data (Task 2).
3. **Lease expired during DELETE and late settlement:** stale token cannot overwrite new state; unsettled-at-claim ACK never terminal even if settlement becomes known before response (Tasks 3–4).
4. **Starvation and overload:** large UNKNOWN backlog, stale candidates and simultaneous expiry/removal still get bounded fair progress; failed DB completion is recovered without hot loop (Tasks 3, 5).
5. **Provider retention and test isolation:** DELETE marker is not physical erasure; ordinary test contexts cannot accidentally run enabled scheduler against fixtures (Tasks 0, 5, 6, 7).
